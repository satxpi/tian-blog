给公众号发草稿，接口回了个错：`45004, description size out of limit`——摘要有大小限制。

可我的摘要是从正文前面截的 35 个汉字。35 个字能有多大？

我把整个请求体打印到终端上，答案就摊在那儿：正文里每一个汉字都变成了 `\u5f00\u53d1` 的形状。35 个汉字，每个变成 6 个 ASCII 字符，210 字节，而微信给摘要的上限是 120 字节。接口一点没说错，是我自己把"35 个汉字"变成了"210 个字符"，还浑然不觉。

至于每个汉字为什么都成了那个形状——因为给接口传 JSON 的时候，我用了最省事的那种写法。程序里的 JSON 序列化默认是"凡是 ASCII 之外的字符，全部转义成 `\uXXXX`"。

这行默认值本身完全合法，`"\u5f00\u53d1"` 和 `"开发"` 在 JSON 里就是同一个字符串，解析出来一模一样。但它俩的字节数差了三倍。

于是就出现了这件事最荒诞的地方：我代码里写的没错，接口报的也没错，两边都正确，可结果是错的。中间那个"没错"的默认值，把一件小事放大成了一场故障。

**从那天起我认了一条：乱码从来不是显示问题，是数据问题。** 你在屏幕上看到一堆问号、一堆错字的时候，数据早在更上游的某个边界上，就已经被改写过了。

## 屏幕是最没用的证人

人对乱码的第一反应，几乎都是去修"显示"。

网页乱码，去检查那行声明字符集的 meta 标签；表格打开 csv 是乱码，去调字体；日志里中文成了问号，去翻终端设置。方向对了一半——显示层的声明确实重要，但它只在一种情况下有用：字节是对的，只是被看错了。

而大多数时候，字节本身已经错了。一段字节被用错误的编码解开之后，再存一次，原始信息就没了。一个 UTF-8 编码的汉字，用 GBK 去解，会得到一两个"看起来也挺正常"的汉字；这两个汉字再被当成 UTF-8 存回去，就彻底定型了。它是"合法"的字符串，只是内容已经不是你写的那句话。

这就是那条著名的"锟斤拷"的来历：UTF-8 里无法解码的字节会被替换成一个"替换字符"，而这个替换字符的字节被 GBK 一解析，就变成了"锟斤拷"三个字。你在 Windows 上见过的那串怪字，本质上是**一堆损坏标记的二次损坏**。它不是在告诉你"编码不对"，它是在说"太晚了"。

所以我后来改了这个习惯：**乱码不在屏幕上查，在边界上查。**

一段数据在一个系统里会过几道关口：从文件读进来、进内存、序列化成 JSON 发出去、过网络、对方接收、再存进自己的库。编码问题是唯一一类**只能在关口处理**的问题，因为每过一次关口，字节都被重新解释一次。关口上不管，进了屋就没人认领了。

## 别用眼睛验收，用字节验收

那次之后我在发布脚本里加了两道检查：发草稿之前先看序列化好的请求体里有没有 `\u` 转义，再看摘要按 UTF-8 算的字节数有没有超过 120。都是十几行以内的事，但它把这类故障从"上线后被发现"提前到了"发出去之前"。

这里有个比记住几个编码名字更值钱的原则：**别用眼睛验收编码，用字节验收。**

因为"看起来正常"在编码这件事上完全不可信。一个 UTF-8 的 csv 文件，在服务器上打开干干净净，双击用 Excel 打开就是一团乱码——Excel 老老实实按系统默认的本地编码去解了。解决办法简单得有点滑稽：存的时候在前面加三个字节的 BOM，Excel 见了 BOM 就乖乖按 UTF-8 解。

可这三个字节又会咬别人一口：有些程序把 BOM 当成正文的一部分，于是你的第一个列名前面永远多一个看不见的字符，用列名取数报"找不到这一列"，你盯着屏幕看半天，那个字段明明就在那儿。这又回到同一条纪律上：看不见的字节，只能靠字节层面的检查发现。

还有一件事得说清楚——**别猜。**

有个流传很久的自欺欺人的做法叫"猜编码"：读进来先按 UTF-8 试，失败换 GBK，再失败换 latin-1。它能"成功"，可成功的标准是"解出来了"，不是"解对了"。GBK 几乎能把任何一段字节解成汉字，它不报错，只是给你错的内容。你后面所有基于这段数据的判断，都建在一堆损坏标记上。

猜得准也不该猜。编码是别人给你数据的**契约的一部分**：要么文件自己写清楚（BOM、XML 声明），要么接口里约定清楚（请求头里带上字符集），要么直接问清楚。契约不明的数据，宁可先摆着。

## 回到那篇草稿

那天我把序列化改成不转义、请求头带上字符集，重新发了一遍，草稿一次就进去了。

从"接口说摘要超长"到"改掉一个默认值"，中间隔着我打印出来看的那一眼。真正救场的不是经验，是那一眼——**编码问题唯一可靠的排查方式，是到字节层面看一眼，而不是盯着屏幕上那堆看不懂的字继续推理。**

后来我把这条规矩推得更远了一点：所有读写文件的地方，一律显式写出编码，绝不用系统的默认值。默认值是给不在乎的人准备的；一旦你的数据和别人的数据要碰面，别人的默认值就是你的 bug。

你写下的每一个字，在抵达读者之前，都会变成一串字节在路上跑。那几个关口，得有人替它盯着。
