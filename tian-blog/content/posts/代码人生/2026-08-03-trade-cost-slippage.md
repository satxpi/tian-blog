# 回测年化 30%，实盘却亏钱？先把交易成本算明白

## 朋友的故事

上个月，一个做量化的朋友跟我吃饭，愁眉苦脸。

他的策略在回测里跑得漂亮：年化 32%，最大回撤 9%，夏普 2.1。曲线平滑得像教科书。他信心满满地上了实盘，结果三个月跑下来，净值跟回测差了十万八千里——年化大概只剩 8%，还动不动就难受。

他说：老田，是不是我的策略失效了？

我问他第一句话：你的回测里，交易成本怎么算的？

他愣了一下：佣金按万 2.5 算的呀，还扣了印花税。

我说：那滑点呢？冲击成本呢？你那个策略一天换手多少？

他不说话了。

这不是他一个人的问题。我见过太多人，把回测当预言，把实盘当意外。其实回测和实盘之间的鸿沟，**第一杀手不是策略失效，而是交易成本被严重低估**。今天就把这笔账算明白。

## 交易成本到底有几笔

很多人以为交易成本就是佣金，大错特错。A 股一笔完整的买卖，成本至少有五层：

| 成本项 | 怎么收 | 大概费率 | 谁在收 |
|--------|--------|----------|--------|
| 佣金 | 双边，按成交额 | 万 2.5 左右（可谈） | 券商 |
| 印花税 | 卖出单边 | 0.05%（2023 年 8 月后减半） | 国家 |
| 过户费 | 双边 | 万 0.1 | 中国结算 |
| 滑点 | 隐性，买卖价差 | 视流动性而定 | 市场 |
| 冲击成本 | 隐性，大单吃价格 | 视订单规模而定 | 市场 |

佣金、印花税、过户费是明面上的，券商 App 里都能查到。真正坑人的是后面两项——**滑点和冲击成本，它们看不见摸不着，却往往比所有显性费用加起来还贵**。

先算显性的：假设你买卖各一次，佣金万 2.5 双边就是万 5，印花税卖出 0.05% 就是万 5，过户费双边万 0.2。加起来，**一次完整换手（买进再卖出）的显性成本大约是万 10.2，也就是 0.1% 左右**。

0.1% 听起来不多？后面算给你看。

## 滑点：回测里最容易被忽略的魔鬼

滑点是什么？就是你下单时看到的价，和你真正成交的价之间的差。

你回测里写着"收盘价买入"，但实盘里，你不可能真的按收盘价成交。流动性好的大盘股，买卖价差可能只有一两分钱；流动性差的小盘股，一档价差就是几毛钱，你一个市价单砸下去，成交价往往比你看到的价差出一大截。

滑点的建模方式，常见有三种：

**第一种：固定滑点。** 最简单，每笔交易固定扣一个点数，比如 0.1%。适合流动性好的品种，做个粗糙的保守估计。

**第二种：比例滑点。** 按成交金额的百分比扣，比如 0.2%。比固定滑点合理一点，但仍然没有考虑你的订单大小对市场的影响。

**第三种：冲击成本模型。** 最接近真实。学术界的经典结论是**平方根法则**：冲击成本大致与订单规模占日成交量的比例的平方根成正比。简单说：

```
冲击成本 ≈ k × √(订单金额 / 日成交额)
```

k 是系数，跟品种有关。这个公式的含义很深刻：**订单越大，冲击成本涨得越快（平方根关系），所以大资金天然吃亏，策略容量是有上限的。**

## 把成本模型写进回测

光说不练假把式。给你看一段最小可用的成本模型，这是我自己的回测框架里截出来的：

```python
import numpy as np

def estimate_trade_cost(notional: float, daily_volume: float,
                        commission_rate: float = 2.5e-4,
                        stamp_rate: float = 5e-4,
                        transfer_rate: float = 1e-5,
                        k: float = 0.15, side: str = "buy") -> float:
    """
    估算一笔交易的总成本（单位：元）。
    notional: 订单金额；daily_volume: 标的当日成交额（元）。
    返回成本金额，回测里直接扣到净值上。
    """
    # 显性成本：佣金双边，印花税卖出单边，过户费双边
    commission = notional * commission_rate
    stamp = notional * stamp_rate if side == "sell" else 0.0
    transfer = notional * transfer_rate

    # 隐性成本：平方根法则冲击成本 + 买卖价差的一半
    participation = notional / max(daily_volume, 1.0)
    impact = notional * k * np.sqrt(participation)
    half_spread = notional * 5e-4  # 假设半价差 0.05%，可调

    return commission + stamp + transfer + impact + half_spread


def apply_costs(nav: float, turnover: float, daily_volume: float) -> float:
    """把成本按换手率折算到净值上，turnover 是当日换手比例（0~1）。"""
    notional = nav * turnover
    cost = estimate_trade_cost(notional, daily_volume)
    return nav - cost
```

注意两个细节：

一是**冲击成本必须用订单金额和当日成交额算**，不能用固定的百分比糊弄。很多开源框架默认只扣佣金，这就是为什么回测曲线那么好看。

二是**成本要按换手率折算到每天的净值上**，而不是只在开仓平仓时扣一次。高频调仓的策略，成本是每天都在流血的。

## 换手率是成本放大器

现在算关键账：换手率怎么放大成本。

假设你的策略年换手 20 倍（这在高频调仓的选股策略里很常见，相当于平均每 18 个交易日就全部换一遍）。每次完整换手的显性成本 0.1%，那么：

```
年化成本 ≈ 20 × 0.1% = 2%
```

看起来还行？别忘了滑点。如果加上滑点和冲击成本，单次换手总成本轻松到 0.3%~0.5%。按 0.4% 算：

```
年化成本 ≈ 20 × 0.4% = 8%
```

**你的策略年化 30%，扣掉 8% 的成本，还剩 22%；再扣掉冲击成本被低估的部分，实盘剩 10%~15% 都算运气好。** 如果策略本身年化只有 12%，扣完成本直接归零，甚至倒亏——这就是很多人"回测赚钱、实盘亏钱"的真相：不是策略失效了，是策略从来没真正赚过钱，回测里的收益全是幻觉。

所以判断一个策略靠不靠谱，第一件事不是看夏普，而是看两件事：**换手率高不高，单次换手赚的够不够覆盖成本。** 一个朴素但有效的标准：单次换手的期望收益，至少要超过单次换手总成本的 3 倍，这个策略才有实盘价值。低于这个阈值，收益全给券商和国家打工了。

## 怎么校准成本模型

模型写好了，参数怎么定？我的做法分三步：

**第一步，模拟盘校准。** 实盘之前，先跑至少一个月的模拟盘（用真实行情撮合的那种，不是回测）。把模拟盘的成交价和当时的最低价/卖一价对比，你就能得到自己真实滑点的分布。别用回测软件自带的模拟，那玩意儿默认滑点为零。

**第二步，小仓位实测。** 拿 5% 的资金实盘跑两周，记录每一笔成交价和你下单时的盘口价。注意，**小资金的滑点和大资金的滑点完全不同**，这一步测出来的是你的下限。

**第三步，压力测试。** 把成本模型的参数往狠了调：滑点翻倍、冲击系数翻倍，看策略还剩多少收益。如果翻倍之后策略就不赚钱了，说明策略的安全边际太薄，实盘迟早出事。**回测里把成本算得越狠，实盘越不容易打脸。**

## 老田的观点

最后说点掏心窝子的。

很多人问我，回测收益打几折才是实盘收益？我的经验是：**没有成本模型的回测，先扣 30%~50% 再说；有合理成本模型的，扣 10%~20%。** 这不是精确科学，但方向不会错——宁可低估自己，也别高估。

还有一句更重要的：**交易成本不是回测的"细节"，而是策略的一部分。** 一个不考虑成本的策略，就像不算油耗就买车——纸面上百公里五个油，开起来十五个，你还以为是路况不好。

把成本算明白，你的回测才配叫回测。不然，那只是一张自欺欺人的曲线图。
