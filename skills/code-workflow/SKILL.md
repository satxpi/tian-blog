# 代码开发工作流

标准化代码开发流程，减少出错和遗漏。

## 工作模式

### 模式A：结对编程（新功能开发）

**触发词**: "帮我实现"、"写个功能"、"开发一个"

**流程**:

```
1. 需求分析
   ├─ 明确输入/输出
   ├─ 识别边界条件
   ├─ 确认异常处理
   └─ 输出：设计方案（简短）

2. 编码实现
   ├─ 先写核心逻辑
   ├─ 处理边界情况
   └─ 添加必要注释

3. 自检清单
   ├─ 语法检查：python -m py_compile <file>
   ├─ 导入检查：确认所有 import 有效
   ├─ 边界测试：空值、极值、异常输入
   └─ 运行测试（如有）
```

### 模式B：代码重构

**触发词**: "重构"、"优化"、"改进这段代码"

**流程**:

```
1. 现状分析
   ├─ 识别问题点
   ├─ 分析依赖关系
   └─ 输出：问题清单

2. 重构计划
   ├─ 列出修改步骤
   ├─ 标注风险点
   └─ 用户确认后执行

3. 分步执行
   ├─ 每步修改后检查语法
   └─ 运行测试验证

4. 对比验证
   └─ 确认功能不变
```

### 模式C：Bug 修复

**触发词**: "修复bug"、"这个报错"、"出问题了"

**流程**:

```
1. 问题定位
   ├─ 分析错误信息
   ├─ 追踪调用链
   └─ 找到根因

2. 修复方案
   ├─ 提出修复方案
   └─ 用户确认

3. 实施修复
   └─ 修改后验证

4. 回归检查
   └─ 确认不影响其他功能
```

## 自检清单

**Python 代码必须检查**:
```bash
# 语法检查
python -m py_compile <file>

# 类型检查（如果有 mypy）
mypy <file> --ignore-missing-imports

# 运行测试（如果有）
pytest tests/ -v
```

**JavaScript/TypeScript 代码**:
```bash
# 语法检查
node --check <file>

# 类型检查
tsc --noEmit

# 运行测试
npm test
```

## 输出规范

**需求分析输出**:
```
## 方案摘要
- **输入**: ...
- **输出**: ...
- **边界**: ...
- **异常**: ...
```

**编码完成输出**:
```
## 完成情况
- **修改文件**: xxx.py
- **自检结果**: ✅ 语法通过 / ⚠️ 需要测试
```

## 注意事项

1. **复杂任务交给 subagent** — 超过 100 行代码的任务，spawn subagent 处理
2. **不确定就问** — 边界条件不明确时，先问用户
3. **改前备份** — 大改动前确认是否需要备份
4. **测试优先** — 有测试文件必须先跑测试

## 示例对话

**用户**: 帮我实现一个函数，计算两个日期之间的工作日数

**助手**:
> ## 方案摘要
> - **输入**: start_date, end_date (datetime 或字符串)
> - **输出**: int (工作日数量，不含周末)
> - **边界**: start > end 时返回 0
> - **异常**: 非法日期格式抛 ValueError
> 
> 开始实现？我来写代码。
